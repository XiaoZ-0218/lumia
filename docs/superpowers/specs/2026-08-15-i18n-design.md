# i18n (English / 简体中文 / 日本語) — Design

Date: 2026-08-15
Branch: `feature/i18n` (cut from `main`)

## Goal

Add a three-locale UI (en / zh / ja) to Lumia with a statusbar language
switcher. First launch follows the OS language; the user's manual choice
persists. All user-visible chrome strings **and** the first-boot welcome
document are localized. Switching languages never touches the user's
current document.

## Decisions (confirmed with the user)

| Question | Decision |
| --- | --- |
| Translate the welcome doc? | Yes — full translation, all three locales |
| Default on first launch? | Follow the system language (`navigator.languages`) |
| Where is the switcher? | Statusbar dropdown, next to the Theme select |

## Approach — chosen over alternatives

**Declarative `data-i18n*` attributes for static HTML + `t()` for dynamic
strings.** Rejected: imperative per-ID assignment in TS (drifts out of sync
with `index.html` silently) and i18next (a runtime dependency for ~60
strings, against the project's no-framework stance).

### Files

```
src/i18n.ts          # core: locale registry, t(), applyStaticTexts(),
                     # onLocaleChange(), initI18n() (builds the switcher)
src/locales/en.ts    # English dictionary (source-of-truth type) + welcome doc
src/locales/zh.ts    # 简体中文 dictionary + welcome doc
src/locales/ja.ts    # 日本語 dictionary + welcome doc
```

Dictionary shape — flat `Record<string, string>` keyed like `'save'`,
`'noFolder'`, `'stats'`, `'welcome'` (the welcome doc is just another key).
en is the type source; the others are typed `typeof en` so TypeScript
enforces key parity at build time. Placeholders use `{words}`-style tokens
replaced by a tiny `t(key, params)` helper — no interpolation library.

### Static text: `data-i18n*` attributes

`index.html` keeps English defaults (no flash-of-wrong-language concerns:
the bundle applies the locale during init, before first paint of the shell
is interactive). Markup:

```html
<button id="save-file" data-i18n="save" data-i18n-title="saveTitle" ...>Save</button>
```

- `data-i18n` → `textContent`
- `data-i18n-title` → `title`
- `data-i18n-aria-label` → `aria-label`
- `data-i18n-placeholder` → `placeholder`

`applyStaticTexts()` (in `src/i18n.ts`) rewrites every marked element in
one pass and is called at init and on every locale change.

### Dynamic strings: `t()` + `onLocaleChange()`

Mirrors the existing `onUpdate()` pattern in `src/editor.ts`:

```ts
t('save')                       // current-locale string
t('stats', { words: 3, chars: 12 })   // "{words} words · {chars} chars"
welcomeDoc()                    // localized first-boot document
locale(): 'en' | 'zh' | 'ja'
onLocaleChange(fn)              // modules re-render their dynamic parts
```

Modules use `t()` **at call time** where the string is recomputed anyway
(`renderStats`, `renderTitle`, `suggestedName`, link prompt, export title
fallback). Modules that render state once (sidebar tab labels, files
header, empty-tree states, Tauri open-button rewrite) subscribe via
`onLocaleChange()` and re-render.

Console messages (`console.error` in sidebar/files) stay English — they
are developer-facing, and repo convention is English for non-UI text.

### Locale resolution order

1. `localStorage['lumia:lang']` if it holds a known locale (user picked).
2. First `navigator.languages` entry matching `zh*` / `ja*` / `en*`.
3. `en` fallback.

The switcher (`#lang-select`, static options in `index.html`, labels shown
in each language's own name — “English / 简体中文 / 日本語”) writes
`lumia:lang` and triggers re-apply. `document.documentElement.lang` and
the exported HTML's `lang` attribute follow the active locale.

### Welcome document

The three welcome docs live in the locale files. `editor.ts` boots with
`welcomeDoc()` instead of the inline `WELCOME` constant. The doc is only a
**first-boot default**: the draft-restore path in `files.ts` (unchanged)
overwrites it when a draft exists, and switching languages later never
re-sets editor content. Consequently the outline/word-count assertions in
the smoke test are locale-stable *within a boot*, by design.

### Stats formatting

`renderStats` uses `t('stats', …)`:
en: `{words} words · {chars} chars` · zh: `{words} 词 · {chars} 字符` ·
ja: `{words} 語 · {chars} 文字`.

## Testing (scripts/smoke.mjs)

Existing sections boot in English (jsdom `navigator.language` is `en-US`)
so current assertions stay green. Two new sections:

1. **[10] Language switcher** — switch to zh via `#lang-select`, assert
   chrome strings flip (root-name, tabs, buttons, stats format), assert
   `lumia:lang` persisted, assert editor content unchanged; switch to ja
   and back to en.
2. **[10b] Second boot (zh)** — new JSDOM with `lumia:lang=zh` pre-set,
   re-import the entry chunk with a cache-busting query (single-chunk
   build re-executes), assert the zh welcome doc rendered and chrome is
   Chinese.

CI (`npm ci && npm test`) exercises both boots on every push.

## Docs & release hygiene

- README / README_CN feature lists gain the language switcher line.
- CHANGELOG `[Unreleased]` gains a feat entry.
- No new dependencies; no AGENTS.md changes needed (follows existing
  `lumia:` storage and module conventions).

## Non-goals

- RTL layouts, additional locales, per-document language detection.
- Translating theme names, file names, or console output.
- Native macOS menu localization (Tauri shell has no menus).
